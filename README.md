# 船舶与航空资产风险监控

交通银行东京分行的独立资产监控页面。正式入口：https://monitor.bocom-tokyo.site/ ，主域名自动跳转；共享测试账号 `test` / `test`，由 Caddy 验证。

## 使用

- 添加船舶时选 shipId、IMO、MMSI 之一，输入一个标识码即可。系统先核对来源身份，再自动读取船名、船型和航次；备注选填。
- 添加飞机时填写注册号，按实体持续跟踪当前、待飞或最近航班。无实时位置但有可核实记录时，显示已降落或未起飞。
- 每艘船检查全部有效风险区域。初始区域为霍尔木兹海峡、亚丁湾；区域可在管理中添加、删除或恢复。边界计入区域，新配置在下一次有效采集时核查。
- 每 10 分钟自动采集。页面每 15 秒读取本地最新记录，浏览详情和更新备注不请求供应商。首次核验身份后立即采集。
- 删除目标会停止采集并移出列表，历史证据保留；恢复默认暂停。详情中可编辑备注及航空延误阈值。
- 船舶、航空独立动态列支持筛选、翻页和输入页码跳转，提供状态、进入/离开区域、延误和取消/备降事件及原始依据。无有效位置时不推断船舶已离开风险区。

## 本地启动

需要 Python 3.11+，在仓库目录运行 `Setup.ps1`、`Start.ps1`，访问 http://127.0.0.1:8000/ 。环境配置参考 `.env.example`。SQLite 位于 `data/risk.db`，不提交仓库。

页面、API 与离线底图由同一 FastAPI 服务提供，无需 Node 开发服务器。服务端以单 worker 运行，定时采集由应用自身执行。`RISK_POLL_SECONDS=0` 可关闭自动采集。

## 数据与范围

仅使用 MarineTraffic 和 Flightradar24。船位使用固定版本的用户 MarineTraffic SDK；船舶身份、船型和航次补充请求暂在适配层，待用户 SDK 完善后统一同步。FR24 使用 FlightRadarAPI 传输和实体解析，补充注册号历史、航班详情及页面分类接口。详细调用见 [SDK 接入](docs/sdk-integration.md)。

未接入付费卫星坐标。仅当来源明确提示新卫星船位且核查有效时显示“岸基未更新 · 有卫星船位”，地图保留最后已知位置。未知船型、机场名和分类明确标注未提供，不人工猜测。

风险围栏是本系统配置的监控范围，不代表官方风险评级或精确水域边界。地图和默认围栏来源见 [地图说明](docs/map-data.md)。

## 开发与部署

接口 `/docs`，契约 `docs/openapi.json`；架构见 [设计说明](docs/architecture.md)，部署见 [服务器说明](docs/server-test.md)。更新前备份代码、配置和数据库，验证迁移后再发布。

后端测试：`.venv/Scripts/python.exe -m pytest -q`。页面模块测试：`node --test tests/test_*.cjs`（PowerShell 可逐个传入文件）。测试替身仅存在于 tests，不会注册到运行系统。

首页为 `index.html`。旧 `/asset-risk.html` 和 `/demo.html` 只保留重定向兼容；演示生成器、模拟源、公开风险信息和 AI 功能已移除。

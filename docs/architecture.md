# 当前架构

浏览器读取 dashboard/timeline → FastAPI → SQLite；定时器每 600 秒调用 Store → Provider → SDK/公开接口。读页面、备注和区域管理不发起外部采集。

## 身份与资产

外部创建契约 Enrollment 只接收类型、一个标识码和可选备注。EnrollmentService 先解析并核实船舶身份或飞机注册号；查询失败不写目标。IMO/MMSI 搜索只采用类型和号码完全匹配的唯一结果，再校验 general 返回身份。来源失败返回 503，格式/身份错误返回 422，重复资产返回 409。内部 MonitorCreate 表示已经解析的资产，数据源由服务端决定。

assets.source_ref 保存船舶 shipId；name 来自来源，monitors.remark 单独保存备注。当前来源返回合法身份的船名后可更新 name，旧值与原始记录 ID 写入配置审计。历史航班实例仍可读取和评估，新 UI 只建立持续跟踪的船舶与飞机实体。

## 全球区域规则

每艘船读取全部 deleted_at=NULL 的 regions。逐个多边形判断，边界计入区域；state.regions 记录各区域的 inside、名称和版本，inside_regions 为当前命中集合。进入、离开、首次发现的事件明确列出区域名；同次多区域同类变化合并成一个事件，完整变化集合及全部区域几何写入不可变证据。

区域集合/几何生成摘要。配置变化后当前状态显示待核查；下次收到有效船位时重新评估。即使船位时间重复，也可对原观察记录建立新评估，保留原始 raw_id/hash 并记录触发采集 ID。删除区域不会被伪造为船舶离开事件。过期位置不参与新的区域判断。

## 证据链

raw_records → observations → evaluations → risk_events；规则和事件不可变。原始响应先单独提交，标准化或规则失败仍能追溯。乱序和过期数据不覆盖有效位置，不重复报警。monitor_context 独立保存最新核查到的航次、卫星提示或无坐标的航班状态。

schema v5 在迁移前备份数据库，保留既有资产、观察、采集、评估、事件和配置审计 ID。旧区域归档，新增两个默认全局围栏；船舶新建规则版本，归档已停用数据源的目标。既有公开信息和 AI 历史表原样保留为存档，应用不再读取或写入；新数据库不会创建这些表。迁移可重复启动但只执行一次。

删除目标可恢复，恢复默认暂停。已停用供应商不能恢复采集。区域删除没有单船绑定约束。SQLite 外键检查与证据内容摘要用于发布前后验证。

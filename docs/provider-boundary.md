# 数据源边界与业务接入评估

更新：2026-09-11。

## 当前分层

`供应商接口 → Provider.fetch → 原始响应存储 → Provider.normalize → Observation → 确定性规则 → Risk Event → 页面`

Provider 是进程内的数据接入层，不需要为了换源单独部署一个中间服务。供应商 URL、鉴权、字段解析、身份匹配留在适配器内。页面只调用本系统 API；围栏与延误计算只读标准字段。

之前已有 fetch / normalize 分层，但来源名称、下拉选项、请求校验中仍存在供应商判断。本次增加 `backend/provider_registry.py` 作为统一注册入口：

- 注册适配器、支持类型、所需标识、数据能力、刷新间隔、有效期和来源署名。
- 前端通过 `/api/v1/public/sources` 生成来源列表和署名；目标与时间线响应包含 source 描述。
- `Store.create_monitor` 根据注册表检查兼容性；只有 position 能力的数据源不能用于要求 flight_times / flight_status 的航班规则。
- 标准请求模型只校验资产字段和格式，不枚举供应商名称；默认 mock-v1 保留为旧客户端兼容默认值。
- 时间线来源取自对应原始记录，不使用目标当前配置覆盖历史来源。

## 换源需要多少工作

如果新来源能提供相同语义的数据，主要工作是实现一个适配器、注册能力和字段要求、配置本地凭证、用供应商样例验证身份和时间映射。规则、Risk Event 和已有页面可继续使用。自动化测试注册了一个新名称的适配器，未修改页面或规则，完成创建、采集、事件和历史来源显示验证。

以下变化仍需要额外开发，不能靠填 URL 解决：

- 从飞机位置扩展为某一天的航班实例，需要可靠的航班实例标识及时间字段；不能只用呼号匹配。
- 新数据类型、新风险规则或新的业务展示仍需扩展模型与页面。
- 飞机换机、供应商同一时间戳修订、批量请求及配额管理需要专门处理。
- 已有监控对象的“在线切换来源”操作界面尚未实现。切源需审计配置变化、重置或隔离规则状态，并明确历史保留规则，不能直接改数据库中的 provider 字符串作为业务操作。
- 目前每个监控绑定一个来源；未实现自动跨源拼接、优先级或故障切源。

## Flightradar24 网页和接口

Flightradar24 提供正式 API，网页会员与 API 订阅是不同产品。技术上可编写网页解析器，但官方服务条款 2.3 明确限制对非 FR24 API 服务进行程序化访问和抓取。网页自身使用的请求接口不是一份稳定的对外接入合同。此次未实现网页抓取或调用网页内部接口。

更直接的架构冲突是数据留存：条款 2.4 / 6.3 涉及缓存期限、持久保存以及与其他实时来源补全数据的限制，而本项目当前长期保存原始响应、观测和事件依据。不能不改存储政策就直接挂上 FR24 数据源；应先取得符合银行审计留存要求的许可或另行约定，再落实保留期及删除机制。

依据：[FR24 服务条款](https://www.flightradar24.com/terms-of-service)、[正式 API 入门](https://fr24api.flightradar24.com/docs/getting-started)。以上为当前接入约束梳理，不代表已购买或取得该服务授权。

## 更贴近业务的数据组合

| 业务 | 接入方向 | 要验证的具体字段 |
| --- | --- | --- |
| 船舶跨洋监控 | 提供地面及卫星 AIS 的正式 API，例如 VesselFinder | IMO/MMSI、定位时间、经纬度、导航状态、目标海域覆盖和数据年龄 |
| 飞机位置 | FR24 正式 API 或其他授权定位源 | 注册号/ICAO24、位置时间、覆盖与可见性 |
| 指定日期航班延误/取消/备降 | 提供航班实例和运行时刻的服务，例如 FlightAware AeroAPI | 航班实例 ID、计划/预计/实际、取消/备降、机场及服务日期 |

VesselFinder 官方接口支持按 IMO/MMSI 查询，并可请求卫星位置。FlightAware 官方 v4 说明列出计划、预计和实际 OUT/OFF/ON/IN 时间及取消/备降标志。字段是否对目标航司/机场和所选套餐实际可用，仍需样例验证。尤其要区分 OUT/IN（离开/到达登机口）和 OFF/ON（起飞/落地），不能混用不同口径计算延误。

依据：[VesselFinder Vessels 接口](https://api.vesselfinder.com/docs/vessels.html)、[FlightAware AeroAPI](https://www.flightaware.com/commercial/aeroapi/)、[AeroAPI v4 字段说明](https://go.flightaware.com/aeroapi-version-4-migration-guide)。

当前免费 AIS 源覆盖有限；ADSB.lol 候选查询选东京附近，但按 ICAO24 跟踪并不限于东京，实际受接收网络和字段能力限制。本次改动没有新增商业数据源，也没有把试跑原型称为已具备业务数据覆盖。

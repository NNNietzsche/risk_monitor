# 真实数据源接入方案

当前只有 Mock，不调用真实 AIS 或航空服务。本文件描述接入步骤，不声称任何供应商已授权或某套餐具备特定能力。

## 供应商确认清单
| 船舶 AIS | 航班 |
|---|---|
| IMO/MMSI 精确查询及身份关联 | 运营航司、日期、出发机场、航段唯一 ID |
| 卫星/地面 AIS 覆盖、更新延迟 | 计划/预计/实际时间的定义、时间戳时区 |
| 原始位置时间与接收时间 | codeshare 区分，换机和跨日 |
| 导航状态、经纬度、缺失字段 | 取消、备降、恢复、供应商修订版本 |
| 轮询频率、限流、历史回补 | 目标机场覆盖、历史查询和回补 |
| 授权内部展示、存储、派生事件、报告使用 | 授权内部展示、存储、派生事件、报告使用 |

VesselFinder、FlightAware 或其他候选方需在选型时核验官方接口和商务条款。
不依赖网页非公开接口，不把试用权限当成生产授权。
AI 默认关闭。启用后会发送限定数量的监控状态、规则、事件和公开信息快照；具体字段和范围见 README，正式接入由宿主限制可发送的业务字段。

## 开发步骤
1. 取得获准样例响应与字段说明，以脱敏样例建立 adapter contract tests。
2. 实现 Provider.fetch 和 normalize，并在 Store.providers 注册明确版本的 Provider 名称。
3. 生产请求使用服务器固定主机白名单和环境变量密钥；前端不能提交任意 URL。
4. fetch 增加连接/总超时、有限重试、429 Retry-After、指数退避和速率预算；日志不得记录密钥。
5. 在落原始记录时保存供应商响应字节或获准存储的完整字段、请求标识、数据源时间、接收时间和内容哈希。
   当前 Mock 原始记录是规范 JSON，真实 HTTP 原字节需增加独立字段/文件关联，不能把重新序列化 JSON 当成原始字节。
6. normalize 验证标识与目标一致，明确时间含义，将非 UTC 转为 UTC；空值不补成 0 或正常状态。
7. 记录供应商数据修订版本，同时间戳修订不能继续简单忽略；增加修订、回补与事件更正机制。
8. 以历史合法样例回放，对比规则结果和人工确认；先影子运行再启用实际监控。
9. 在正式内网部署前完成身份认证、角色权限、日志脱敏、保留期限、备份恢复和依赖安全检查。

## 接入现有情报 / 报告系统
建议从 GET /api/v1/events 读取统一事件，根据 monitor_id 和时间范围查询，
再获取 /events/{id} 形成事实与证据包。第一版不增加消息队列。
正式报告引用 event_id、数据时间、rule_id 和来源；AI 输出单独存储，
不能回写事实字段、延误计算和区域判断。
当前 ai_runs 已保存模型、提示词版本、引用事件/新闻的输入快照及生成时间。
股票/企业扩展共用监控、Provider、采集、评估和事件框架，各自增加领域状态及规则。

## 上线前架构增量
MVP 的单进程串行采集仅适合小规模。规模增长后先增加持久任务队列/租约、幂等键、
可恢复的 received 原始记录处理任务、供应商限流预算与 PostgreSQL，再评估是否拆服务。
不直接把 uvicorn workers 调大，否则会重复调度。当前采集中断后原始记录可追溯，但未实现自动恢复处理。

# Demo 对照及本次偏差复盘

2026-09-25 航空更新优先于下文旧约定：按注册号持续跟踪，显示当前/最近航班与航线；FR24 机型、分类取接口原文，缺失不人工填写或猜测。船舶修改按用户最新指示暂缓。验收记录见 [aircraft-tracking.md](aircraft-tracking.md)。

参考：Git `01b6557:demo.html`。本次核对日期：2026-09-24。

## 偏差与原因

1. 最初迁移主要复用了导航、布局和视觉样式，没有把 demo 中的业务字段逐项建立为验收清单，遗漏了船型、机型和客货用途。
2. 接真实数据时，以当前 API 能返回的字段主导了页面内容，把来源真实性这一调试/追溯信息放到了列表，占用了本应用于业务分类的位置。数据源没提供字段，应当保留该字段及缺失状态，而不是换成另一个字段。
3. 为了明确原型中模拟与真实的区别，新增了每项来源标签，但没有说明这是相对参考界面的产品变化。需要追溯来源，不代表必须占用主列表空间。
4. 验证重心是采集、规则、证据链和接口兼容，没有直接检查 demo 字段、完整管理流程和外部调用次数。测试通过只证明已测范围，不代表产品需求完整。
5. MVP 实现了创建与暂停，却没有补齐删除及区域引用管理，也没有在交付时明确列出这项缺口。用户只能追加对象，无法整理现有监控。

这些是实现和验收方法的失误，不是用户描述不清，也不能用“只是 MVP”解释掉已经给定的要求。

## 分类规则与依据

分类保存为目标的资产台账属性 `profile`；每次人工修改记配置审计。显示时人工维护值优先，否则使用标准化数据中的来源字段；两者都没有则明确缺失。分类仅用于展示，不参与风险计算。

当前 Digitraffic 适配器附带读取船舶静态资料（缓存 24 小时），只有 MMSI 匹配时才采用船型。AIS 70–79 只表示货船，不能细分成集装箱或散货船；80–89 只表示液货船大类，不能保证都是油轮。精确子类需资产台账或更完整的供应商资料。依据：[USCG AIS 类型定义](https://www.navcen.uscg.gov/ais-class-a-reports)。

当前 ADSB.lol 可提供机型，但没有可靠的客货用途字段；不会从 B763/B777/A350 或呼号猜用途。人工录入时应依据已核实的资产信息。演示种子明确填写模拟船型、机型和用途，真实目标不套用演示分类。

## 管理与刷新验收

- 删除后目标从默认列表、地图、数量统计及自动采集集合中消失；历史时间线、事件、原始记录和配置审计继续可查。
- 恢复不新增身份或覆盖历史，恢复后保持暂停，启用由用户操作。相同唯一标识已存在于删除记录中时，通过管理入口恢复。
- 在用区域不可删除，暂停的目标也算使用；删除该目标后可删除区域。删除区域不会破坏历史证据，重启也不会自动恢复它。
- 船舶刷新只处理启用的船舶；航空刷新处理启用的飞机实体及航班实例。暂停/已删除目标不产生外部请求。
- 默认自动采集 3600 秒，启动后等待首个周期；手动按钮可立即发起采集，但保留 Provider 的最短间隔及失败退避。
- 页面每 15 秒只读取本地缓存，不请求供应商。位置是最近一次观测，不是实时航迹；原有数据年龄校验和过期提示保留。
- 后端测试覆盖删除、恢复、区域引用、历史保留、分类来源和分组采集。前端测试直接检查 demo 的业务字段格式，验证无真实/模拟尾缀，同时继续测试地图高亮。

# 公开真实数据接入（2026-09-11）

## 现在可以做什么

- 船舶：`digitraffic-v1` 按 MMSI 读取真实 AIS 定位，用原有围栏规则生成事件。
- 飞机：`adsblol-v1` 按 ICAO24 查询位置，并校验注册号；以飞机实体保存，不伪造航班实例、计划时刻、起降机场或延误结论。
- 原模拟源保留。每个目标、历史时间线和原始记录分别标注来源；采集失败不回退模拟数据。
- 页面“接入公开数据”读取最近有信号的候选船舶、东京附近飞机，选择目标后添加并采集。也可在“添加监控对象”中直接填写 MMSI 或飞机注册号 + ICAO24。

## 数据源和限制

| 来源 | 接口 | 能力 / 覆盖 | 许可 |
| --- | --- | --- | --- |
| Fintraffic / Digitraffic | `https://meri.digitraffic.fi/api/ais/v1/locations?mmsi=…`，`/api/ais/v1/vessels/{mmsi}` | 芬兰周边水域 AIS，不保证全球指定船舶可见 | CC BY 4.0 |
| ADSB.lol | `https://api.adsb.lol/v2/icao/{icao24}`，`/v2/lat/35.55/lon/139.78/dist/100` | 社区接收机覆盖的飞机位置；没有完整计划、预计和实际航班时刻 | ODbL 1.0 |

官方说明：[Digitraffic 海事接口](https://www.digitraffic.fi/en/marine-traffic/)、[使用说明](https://www.digitraffic.fi/en/support/instructions/)、[ADSB.lol API](https://www.adsb.lol/docs/open-data/api/)。页面保留署名与许可链接。商业上线时需针对覆盖、可用性及数据库许可义务评估正式数据合同。

ADSB.lol 要求 User-Agent 包含有效联系信息。在本地 `.env` 设置 `PUBLIC_DATA_CONTACT=你的联系邮箱或项目联系页面`，再运行 `Start.ps1`。它只用于 ADSB.lol 请求头，不写入原始响应或提交到仓库。无 API 密钥；未设置时飞机采集报告配置缺失。

公开 ADS-B 位置不能可靠证明某日航班准点、取消或备降。航空位置目标的状态明确为“仅位置 · 航班未评估”。真实延误监控仍需要提供航班实例和时刻的航空数据源。香港机场公开历史接口虽可取到前一天离港记录，但不能冒充实时航班延误源；本次未接入。

## 采集与审计

- 每目标两次采集至少相隔 60 秒；手动重复点击返回 `throttled`。调度器仍按原配置检查所有启用目标。
- 相同请求缓存 45 秒，候选查询 120 秒，候选船名元数据 1 小时，监控船舶的分类元数据 24 小时。默认每 30 分钟采集一次，船舶/航空可分别手动刷新。失败请求冷却至少 120 秒；HTTP 429 的 Retry-After 若更长则遵守该值。不并发轰炸、无自动重试循环。状态数据缺失、过期或身份不符时保留上次有效位置并标记健康状态。
- AIS 数据时间取 `timestampExternal`（毫秒），不使用分钟内秒数 `timestamp`。飞机数据时间取响应 `now`（毫秒）减 `seen_pos`（秒）。不把抓取时间充当观测时间。
- 保存请求 URL、抓取时间、HTTP 状态、有限响应头、HTTP 解压后的响应体字节（Base64）和解析结果；现有 SHA256、规则版本、观测记录及事件证据继续关联。
- 飞机位置有效窗口 120 秒，船舶 900 秒；未来超过 60 秒拒绝。重复、乱序不产生新事件。数据缺失不会被解释为准点。
- 首次升级前自动备份旧库为 `data/risk.db.before-aircraft.bak`，重建监控对象约束以允许飞机实体，保留 ID、历史事件及审计记录并检查外键。

## 本地试用的测试围栏

“波罗的海测试围栏（仅功能测试，非风险评级）”是为了验证真实位置 → 围栏规则 → 风险事件闭环而设置的矩形，范围为 18°E–30°E、58°N–66°N。船舶真实位置落入它时，事件表达的是测试围栏条件满足，不能解释为该海域存在实际风险。真实业务请另建经确认的监控区域。

## 地图多目标行为

“显示全部目标”包含该图所有已有有效定位（也含灰色历史/暂停目标），按坐标边界调整视野；目标分散时缩小，聚集时放大。当前是平面世界底图，跨 ±180° 经线的目标可能使视野扩大到接近全球。地图刷新保留当前视野，新增目标后可再次点击此按钮。

## 后续正式接入

继续通过统一 `fetch / normalize` Provider 接口接入供应商。全球 AIS 要求 MMSI/IMO 解析、数据时间和位置；航班供应商必须区分飞机与服务日期下的航班实例，并提供计划、预计、实际时间及取消/备降状态。接入时建立字段映射和能力声明，保留供应商原始响应，使用现有确定性规则，AI 仍只负责解释。
